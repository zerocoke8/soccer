# 2.5D 경기 화면 · 스프라이트 시험 계획 (브랜치 `outgame-sprite`)

> 상태: 구현 계획 · 2026-10-05 · 브랜치 `outgame-sprite` (웹 시험판 https://zerocoke8.github.io/soccer/sprite/ — 저장 키 `soccer-sprite.`).
> 레슨판 (`outgame-lesson`, /lesson/) · 본편 (main) 은 바꾸지 않는다. 엔진 (`js/engine/*`) · 데이터 규칙 · 밸런스는 바꾸지 않는다 — 화면만.
> **[가정]** = 기획자가 아직 정하지 않은 값, **[구현 결정]** = 이 계획이 정한 세부. 둘 다 §8 에 모은다.

## 0. 기획자 결정 (2026-10-05)

1. **2D 레이어로 만드는 2.5D.** 배경은 3D 엔진이 아니다. 생성 그림 층 (하늘 · 관중석 띠 · 잔디 바닥 · 선수 스프라이트) 을 겹치고, 카메라는 확대 · 이동만 한다 (돌리지 않는다).
2. **카메라 각도 = C (위에서 약 30° 내려다보기).** 쿼터뷰 (대각선 경기장) 는 쓰지 않는다.
3. **스프라이트는 한 방향만 그린다 (1번 안).** 오른쪽을 보는 "거의 옆모습" (몸 약 75° 돌림) · 2.5등신 · 위에서 30°. 왼쪽은 좌우 반전. 뒷모습은 그리지 않는다 (해 보고 꼭 필요하면 대기 · 달리기만 나중에, 약 1.3배).
4. **카메라 = 공을 따라간다 (평소)** · **직접 결정할 때 (버튼을 고르는 동안) 더 확대** · 킥오프 · 골 뒤 · 포제션 시작에는 잠깐 풀코트.
5. **경기장 바닥도 생성 그림** (위에서 똑바로 본 잔디 그림을 화면에서 눕힌다). 규칙 구역과 맞아야 하는 흰 선 · 박스 · 원 · 구역 강조는 같은 바닥 위에 정확한 자리로 그린다 (분필선 느낌).
6. **스프라이트 크기는 240px 한 가지** (원본 높이 240, 화면 기준 선수 키 약 64 ~ 72px, 결정 확대 2배에서도 폰에서 거의 1:1). 400px 판은 만들지 않는다.
7. 동작 영상 (시댄스 2.5 / 클링 3.0 → 프레임 → 스프라이트 시트) 은 이 계획 다음 단계 — 지금은 한 장짜리 정지 스프라이트 (기준 그림) 로 화면 구조 · 카메라를 먼저 만든다.

## 3. 투영 (`js/ui/view25.js` — 순수 함수, 테스트한다)

- **판 (ground plane) 좌표**: 판 = 폭 `PL` × 깊이 `PD` (판 px). 경기장 (필드) = 판 안의 `FL × FD` 사각형, 둘레에 런오프 `RU` (길이 방향) · `RV` (깊이 방향). [구현 결정] 시작값 `FL = 1244` (= 지금 필드 폭), `FD = 980`, `RU = 70`, `RV = 60`.
  - 필드 % → 판 좌표: `u = RU + (y / 100) · FL` (y = 골 방향, 0 = home 골 = 왼쪽), `v = RV + (x / 100) · FD` (x = 0 이 먼 터치라인 = 화면 위).
- **호모그래피** `Hm` (3×3): 필드 사각형 네 귀퉁이 → 화면 (필드 영역 `W × H` px, 지금 1244×528) 의 대칭 사다리꼴.
  - 가까운 터치라인 (v = RV + FD): y = `nearY` (H − 6), x = 0 ~ W. 먼 터치라인 (v = RV): y = `farY` (약 34), x = `W·farInset` ~ `W·(1 − farInset)`, `farInset` 0.085 [구현 결정 — 위에서 30° 의 완만한 원근].
  - 4점 → 3×3 해법 (표준 DLT). 판 밖 (런오프) 도 같은 식으로 투영된다.
- `project(x, y)` → `{ sx, sy, s }`: 화면 px 와 그 자리의 크기 배율 `s` (= 그 깊이에서 u 방향 1 판 px 의 화면 길이 ÷ 가까운 터치라인에서의 같은 값).
- `project3(u, v, h)`: 판 위 높이 h (판 px) 의 점 — 화면 y 에서 `h · s · liftK` 를 뺀다 (세운 물체 · 공 높이 · 골대). [구현 결정] liftK = 0.92 (30° 에서 수직 길이가 거의 그대로 보이게).
- `unproject(sx, sy)` → 필드 % (역행렬) — `fromPx` 대신.
- `cssMatrix3d()` → `matrix3d(...)` 문자열: 판 div (PL × PD, `transform-origin: 0 0`) 에 걸면 화면에서 `project` 와 정확히 같은 자리에 판 픽셀이 놓인다 (z = 0 점은 (u, v, 0, 1) → (X, Y, Z, W), 화면 = (X/W, Y/W)). 테스트가 문자열을 파싱해 같은 점을 비교한다.

## 4. 화면 구조 (2.5D 모드, `js/ui/screens/match.js` · `css/match.css`)

```
.pitch (그대로: 1268×708, overflow hidden)
  .w-sky                    하늘 그라데이션 (카메라 밖, 이동량 30% 시차) — 2.5D 모드만
  .m-field (그대로 자리 · W×H)
    .w-cam                  ★ 카메라 층: transform = translate(...) scale(z), origin 0 0 — 아래 전부 이 안
      .w-strip              먼 쪽 배경 띠 (투영된 먼 터치라인 뒤에 세운다)
      .w-ground             판 div (PL × PD) + matrix3d — 잔디 그림 · .pitch-bg (구역 · 선 · 강조) 를 판 안에
      svg.w-goals           서 있는 골대 두 개 (project3)
      .tok-layer / .m-ball / svg.pitch-svg / svg.pitch-svg.top / .pop-layer   (지금 그대로, 좌표만 투영)
    .charge-veil · .goal-fx (카메라 밖 — 지금처럼 필드 전체)
```

- 모드 판단 한 곳: `store.js` 에 `D25` (주소 `?d25=1` / `?flat=1` · `SPRITE_SITE`) + 테스트용 바꾸기 함수. `match.js` 는 모드에 따라 `toPx` / `fromPx` / `dirPx` 를 고른다 (평면 모드 코드 경로는 한 줄도 바뀌지 않게 — 기존 테스트 그대로).
- **토큰 (2.5D)**: 앵커 = 발. `--ts` (깊이 배율) 로 크기. 구조: `.tok-ground` (발밑 그림자 · 역할 고리 = 납작한 타원: carrier 금 · defender 흰 · receiver 점선 · cover 점선) → `.tok-figure` (스프라이트 `img` 또는 얼굴 원 스탠디) → `.tok-bar` · `.tok-name` (발 아래) · `.tok-bubble` (머리 위). 상태 클래스 (`fallen` · `dive` · `header` · `steal` · `claim` …) 는 `.tok-figure` 에 걸리게 CSS 를 2.5D 판으로.
  - 크기: 스프라이트 키 `SPR_H = 72 · s` (가까운 터치라인 72px), 스탠디 얼굴 원 지름 `40 · s`.
  - 방향: `.face-l` 이면 그림만 `scaleX(-1)` (이름표 · 바는 뒤집지 않는다).
  - 겹침: `z-index = 100 + round(sy)` (차지 · 컷인 층은 지금처럼 위).
- **이름표 · 말풍선 자리 고르기**: `tokenRect` · `labelCands` · `bubbleCands` 를 2.5D 판으로 (세로로 긴 사각형: 발 기준 위로 키만큼). CSS `lbl-*` · `bub-*` 오프셋도 같은 식으로 (JS 상자 = CSS 자리).
- **배치 간격**: `computeLayout(view, { aspect, tokenSize })` 에 판 기준 값 `aspect = FD / FL`, `tokenSize = 46 / FD` [구현 결정] — 가까이 선 두 선수가 몸 폭만큼 떨어지게.
- **공**: 투영 · 크기 `s` 배, 발 앞 (공격 방향으로 `0.35 · 폭`). 높이 있는 이동 (크로스 · 롱패스 · `arcBall`) = 바닥 직선 위로 `sin(πt) · 90 · s` 만큼 뜬다 + 바닥 그림자. `curveCtrl` 의 2.5D 판 = 위로 뜨는 곡선 (화살표 · 자취도 같은 모양).
- **골대**: 두 기둥 (`v = 중앙 ± 골 폭/2`, 높이 `GH`) · 크로스바 · 뒤 그물 (얇은 선 격자) — 흰 선 SVG. 골문 쪽 (`goalPt`) 은 지금 규칙 그대로.
- 레슨 화면은 바꾸지 않는다 (`.lesson-screen` 은 평면 그대로 — 2.5D CSS 는 `.match-screen.d25` 아래로만).

## 5. 카메라 (D2)

- 상태 `{ cx, cy, z }` = 화면 (필드 영역 W×H) 가운데에 올 월드 점 (투영 후 px) · 배율. `.w-cam { transform: translate(W/2 − z·cx, H/2 − z·cy) scale(z) }`.
- 범위 고정: 보이는 창 (W/z × H/z) 이 월드 사각형 (투영된 판 + 위쪽 배경 띠) 밖으로 나가지 않게 cx · cy 를 자른다. z = 1 이면 언제나 전체.
- **목표 고르기** (순수 함수 `cameraTarget(state, layout, view)` — 테스트):
  | 상황 | z | 가운데 |
  |---|---|---|
  | 경기 시작 첫 비트 · 골 연출 · 킥오프 배치 · 경기 끝 · ⏭ | 1 | 전체 |
  | 평소 (공 따라가기) | `Zf` = 1.4 (4배속 1.2) | 공 + 공격 방향으로 앞쪽 8% 미리 보기 |
  | 직접 결정할 때 (`paused(view)` — 공격 · 수비 · GK 배급) | `Zd` = 2.0 | carrier · defender · (보이면) cover 수비 · 고른 받는 선수 의 사각형 가운데. 그 사각형 (+여백 · 머리 높이) 이 창에 안 들어가면 z 를 Zf 까지 낮춘다 |
  | 액션 중 (`actionPhase`) | 지금 z | 공이 갈 곳 (패스 받는 선수 · 드리블 도착 · 슛 골문) |
- **움직임**: `.w-cam` 의 CSS transition — 결정 확대 들어가기 0.35s · 액션 `--t-act` · 재배치 `--t-move` (토큰과 같은 이징). 줄인 움직임 (reduced motion) = 순간 이동. ⏭ = 전체로 순간.
- **글자 크기 유지**: 확대해도 이름표 · 말풍선 · 결과 팝 · 링크 글 · 화살표 끝 글자는 화면 크기 그대로 — `--cam-z` 로 `scale(1 / z)` (자리 고르기 상자도 ÷ z, 화면 밖 판정은 지금 창 (월드 좌표) 기준).
- 하늘 (`.w-sky`) 은 카메라 이동의 30% 만 따라간다 (시차).
